1 · The Locked Spec (what we are building)

Cognitive job: Perform the mechanical portion of senior code review on a pull request — reasoning independently across four concerns (security, quality, tests, docs), each grounded in retrieved codebase context — and emit structured, evidence-bearing findings. Post automatically only when confident; escalate otherwise. The scarcity it relieves is senior-reviewer attention (L0). It optimizes for selectivity, not coverage: surfacing findings worth a senior's time and deferring the rest.

Inputs: a GitHub pull_request webhook (opened / synchronize) carrying the PR diff — untrusted, attacker-controlled; plus three memories: semantic (repo code chunks), episodic (past reviews & disputes), procedural (team conventions / ADRs / severity policy)  →  Outputs: one structured review posted to that PR — a list of Finding{agent_type, severity, category, summary, file_path, line_start/end, suggestion, confidence, rationale} — plus one append-only agent_events row per action (span / llm.call / tool.call / decision) carrying cost, latency, and outcome.

Autonomy level: Level 3 — "human handles exceptions" on the 5-level spectrum, with an escalation path to Level 4 ("human decides, system prepares") on CRITICAL. Chosen by the three factors: consequence of error (a missed injection is dangerous), reversibility (a posted review can be disputed and removed), maturity (this system has earned nothing yet — start high-oversight and reduce).  |  Human-in-the-loop points: (1) overall_confidence below threshold → approval queue instead of posting; (2) any CRITICAL finding → escalate/page regardless of confidence; (3) developer disputes a posted finding → dispute route + feedback capture; (4) BudgetGuard hard-block on daily cap → human unblocks.

Failure tolerance: degrade to slower-but-correct, never fast-but-wrong. A false negative (missed finding) is acceptable — a human still reviews. A confidently-wrong posted finding is not: it burns the trust the whole system runs on. Named modes carried from the 0.2 catalog: hallucination-in-critical-path · tool/API timeout · orchestration deadlock · the "almost-right" problem · human bottleneck · feedback-loop poisoning · idempotency gap. Each has a named defense and a matching invariant in context-graph.json.  |  Trust boundary: hostile. The PR diff and every retrieved code chunk are attacker-controlled text that flows directly into four LLM prompts, and the webhook endpoint is public. Defenses: HMAC-SHA256 signature verification before any work; idempotency on X-GitHub-Delivery; an instruction hierarchy that wraps diff/context as data that can never introduce, override, or terminate system instructions; capability-scoped tools; secrets in .env, never in source or git.

Span-of-control verified. Agent roles have defined contracts. Failure path for every agent type is handled. Consensus mechanism chosen if needed. — consensus = dedup-by-(file,line) keeping highest confidence, noting agreement

Phase 10 — Observability & Tracing → M6

Every agent span captures latency + token count + tool result + cost. Alerts on p99 latency, error rate, and cost drift. Prompt traces searchable.

Phase 11 — Security Architecture → M3, M8

Threat model exists with specific adversary categories. Prompt injection mitigated with instruction hierarchy and sanitization. RBAC implemented. Audit trails are append-only and tamper-evident.

Phase 12 — Reliability Engineering → M3, M4, M8

Every outbound call has circuit breaker + timeout + retry with idempotency. Checkpointing strategy allows resumption after crash. No operation has side effects on retry that it didn't have on first execution.

Project-specific success criteria (from the study, not the kit)

A forged webhook signature is rejected before any work is done; a replayed X-GitHub-Delivery produces exactly one review
All four specialists run concurrently — proven by overlapping span timestamps in agent_events, not by assertion
Every posted Finding carries a non-empty rationale and a line that exists in the diff
A review can be fully reconstructed from agent_events alone: SELECT … WHERE review_id = $1 ORDER BY ts
The HITL gate routes all four rows of the L7 table correctly (high-conf → post · low-conf → queue · CRITICAL → escalate · dispute → feedback)
Swapping the LLM or GitHub client for its fake changes no file outside tools/ and integrations/
